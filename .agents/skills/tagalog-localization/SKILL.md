# Tagalog localization

Translate directly using your own language understanding. This is a project-created skill, not a Google product or a certified translation service.

Use clear, conversational Tagalog suited to the intended reader. Prefer familiar terms over literal or unusually formal translations. For farmer-facing copy, useful terms include palay (rice crop), munggo (mungbean), bukid (field), patubig (irrigation), badyet (budget), pag-agos ng tubig (drainage), and mamimili (buyer). Retain familiar technical terms when a forced translation would be harder to understand.

Preserve names, URLs, units, currency, numeric assumptions, constraints, and uncertainty. In AniNow, distinguish archived NASA observations from fictional software examples. Translate unknown, unavailable, and unconfirmed statuses without turning them into recommendations or confirmed facts. Do not claim native-speaker or agricultural-expert review unless it happened.

Follow the application's localization structure. Keep UI strings in its message catalog; include navigation, forms, options, validation, status messages, dialogs, source descriptions, and accessible labels. Keep machine identifiers and saved data stable across languages. Use locale-aware date display without changing date input values or calculation semantics.

Provide an obvious English/Tagalog control using language names, with keyboard access, selected-state semantics, and the correct document language. Switching must preserve form values, comparisons, and saved plans. Remember the preference when browser storage is available.

Allow room for longer translations and preserve readable font sizes. Check phone and desktop layouts, dynamic content, round-trip switching, persistence, and the existing decision flow. Record translations as AI-authored drafts unless qualified reviewers have reviewed them.
